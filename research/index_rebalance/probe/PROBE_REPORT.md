## 四、名单一致率核对

两条口径都做了：

### 4.1 自动核对：公告正文自述 vs 抽出名单（96.7%）

2021-11 起的公告正文明写「沪深300指数更换19只样本」，可与此后抽出的名单条数逐一对照：

```
可自动核对项: 30   一致: 29   一致率: 96.7%
```

唯一不一致的是 **2020-11-27（公告 11514）**：正文自述沪深300 更换 26 只，抽出 55 只。
原因是该公告把**沪深300 与中证香港100 的名单混在同一分节**，属于源本身的表述歧义，
不是抽取错误。该条已单独标注，研究时应剔除或人工拆分。

> 过程说明：首次跑出的一致率是 **44%**，排查后确认是**我的解析器 bug** ——
> PDF 里股票名可能含空格（如「陕国投 A」），而我把名称段写成 `\S+` 导致整行失配、
> 每节少算几只。修正后升到 96.7%。**这个 bug 已修，记录在此以便复核。**

### 4.2 人工核对（建议你在官网抽查）

自动核对只能证明「正文与名单自洽」，**不能证明与官网最终发布一致**。
建议人工抽查以下 3 次（明细见 `consistency_check.csv`）：

| 抽查对象 | 官网入口 | 核对点 |
| --- | --- | --- |
| 2026-05-29（最新） | csindex.com.cn → 指数代码 000300 → 相关资料 → 拟生效样本 | 沪深300 调入 19 只是否与 CSV 一致 |
| 2024-11-29 | 同上 | 中证1000 调入 100 只 |
| 2022-05-27 | 同上 | 沪深300 调入 28 只 |

### 6.1 结论

**通过（有条件）**：

- ✅ 事件数（33）、纳入量（1,789）、一致率（96.7%）**均达标**
- ⚠️ **时间范围从 2020-11 起**，不是 2018 起 → 样本量比预期少约 6 次调整
- ⚠️ **行情窗口未验证**（本机无数据）

**对研究设计的影响**：若坚持 2018 起，需另找源（见 6.3）；若接受 2020-11 起，
样本为 **12 次调整 / 33 个指数×事件 / 1,789 个纳入观测**，对事件研究法而言
样本偏小但可用 —— 建议**放宽为面板回归而非单事件 CAR**。

### 6.2 已知风险

| 风险 | 说明 |
| --- | --- |
| WAF 限流 | 详情接口突发 ~20+ 次请求即 403，持续约 10–15 分钟。脚本已放慢到 2–6 秒/次并缓存详情 JSON，**首次全量约 3 分钟**，之后命中缓存秒级 |
| 附件格式两代 | 2021 及更早是 **XLSX**（文件名却写 `.pdf`），2022 起是真 PDF。解析器按 magic 分派 |
| 源歧义 | 2020-11-27 公告混排两个指数；另有「方案」与「结果」两份公告内容重复，需按公告日去重 |
| 早期缺口 | 2018–2020 年无完整名单，**无法通过技术手段补齐** |

### 6.3 若要补齐 2018–2020

## 七、建议的数据表结构（仅设计，不落库）

```sql
-- 调仓事件主表：一行 = 一次「指数 × 调整」
CREATE TABLE index_rebalance_event (
    event_id        INTEGER PRIMARY KEY,
    notice_id       INTEGER NOT NULL,      -- 中证公告 id，唯一溯源
    index_code      TEXT    NOT NULL,      -- '000300' / '000905' / '000852'
    index_name      TEXT    NOT NULL,      -- '沪深300' ...
    announce_date   TEXT    NOT NULL,      -- 公告日 YYYY-MM-DD
    effective_date  TEXT,                  -- 生效日（正文解析，可能为空）
    replace_count   INTEGER,               -- 公告自述更换只数（用于自检）
    in_count        INTEGER NOT NULL,      -- 实际抽到的调入数
    out_count       INTEGER NOT NULL,      -- 实际抽到的调出数
    source_url      TEXT,                  -- 附件 URL，便于复核
    created_at      TEXT    NOT NULL,
    UNIQUE(notice_id, index_code)
);

-- 名单明细：一行 = 一只股票在某个事件里的进出
CREATE TABLE index_rebalance_member (
    event_id        INTEGER NOT NULL REFERENCES index_rebalance_event(event_id),
    direction       TEXT    NOT NULL,      -- 'in' 纳入 / 'out' 剔除 / 'alt' 备选
    symbol          TEXT    NOT NULL,      -- 6 位裸代码，如 '600519'
    name            TEXT    NOT NULL,      -- 证券简称（原样，可能含空格）
    alt_rank        INTEGER,               -- 仅备选名单有排序
    PRIMARY KEY (event_id, direction, symbol)
);

CREATE INDEX idx_reb_event_date ON index_rebalance_event(effective_date);
CREATE INDEX idx_reb_member_sym ON index_rebalance_member(symbol);
```

**字段设计要点**

| 要点 | 原因 |
| --- | --- |
| `notice_id` 唯一且必填 | 中证公告 id 稳定，是所有数据的溯源锚点 |
| `announce_date` 与 `effective_date` 分开 | 事件研究的窗口以**公告日**为 T0，生效日是另一个时点；实测两者相差恒 14 天 |
| 保留 `direction='alt'` 备选名单 | 备选名单本身有研究价值（候补是否更强势），别丢 |
| `replace_count` 冗余存自述值 | 便于持续自检解析质量（本次一致率就是靠它对出来的） |
| `symbol` 存裸代码 + `name` 原样 | 名称含空格/特殊字符（「陕国投 A」），**不要清洗**，否则对不上源 |
| 不加 `is_regular` 硬编码 | 早期公告标题不含「定期调整」，靠标题判断会漏；用 `notice_id` 白名单更稳 |

**已确认不需要的表**：成分快照表（当前成分可由 `index_stock_cons_csindex` 实时取，
无需落库；且它只有当日快照，存了也无法回溯）。
