# XTick 历史竞价补充

本轮只加一条默认关闭的补充链路：官方「竞价数据-历史接口」。它不替换 TickFlow / fuyao，不写入主行情，不参与评分、风控或交易触发。

公开契约来自 `http://xtick.top/assets/apidoc.json`（文档页 `http://xtick.top/doc` 的目录数据），路径 `/doc/hot/bidhistory`。2026-11-09 生产侧曾观察到该接口返回 HTTP 200，正文是 ZIP，里面有 `data.json`：单票 1 行，`code=all` 同日 5580 行，去掉 `seq` 仍是 1 行。本仓库用 fixture 复现这种封装。**fixture 通过不是生产验收。**

## 实际新增的数据

只新增这一张补充卡上的字段，来源标记为 `xtick` / `bidhistory`：

| 官方字段 | 展示名 | 处理 |
| --- | --- | --- |
| `price` | 价格 | 原值。这是该条历史记录上的价格，不是主行情最新价 |
| `close` | 前收 | 官方说明是前收盘价，响应里只叫 `prev_close` |
| `jjzf` | 竞价涨幅 | 按百分数展示。公开样例 `price=11.08`、`close=11.09`、`jjzf=-0.09`，与 `(price-close)/close×100` 一致。不换算进主行情的小数制 `change_pct` |
| `jjl` / `jje` | 竞价量 / 竞价额 | 原值。官方没写单位 |
| `nol` / `noe` | 未匹配量 / 未匹配额 | 原值。这是 fuyao 竞价快照和本地 1 分钟 K 都没有的字段 |
| `trend` | 方向 | 官方枚举：`-1` 主动性卖，`0` 中性盘，`1` 主动性买 |
| `seq` | 原值 | 见下文，不翻译成确定含义 |
| `time` | 上游时间 | 毫秒时间戳转北京时间。样例是当日 `00:00:00`，界面写明这不是 09:25 |

公开样例满足 `金额 = 价格 × 数量 × 100`。等式成立时只做标注，不把数量改写成手，也不写入主行情成交量。

界面在「异动监控 → 竞价异动」。fuyao 未配置时，风向标和全市场扫描仍是原来的空态，这张卡单独出现，默认也不请求上游。

## 为什么只选这一小批

fuyao 竞价扫描只在交易日 09:25:30–09:28:00 抓快照，盘后不补，快照本身没有未匹配量和方向。XTick 这条历史接口按官方说明只保留集合竞价终态和开盘数据，一次可以补上主源没有的未匹配量、未匹配额和方向，而且生产侧已经看到真实的 ZIP 包。

范围停在这里，是为了少打上游：

- 默认单票、单日、手动点查询。`code=all` 要另开 `XTICK_BIDHISTORY_ALLOW_ALL`，因为生产观察同日有 5580 行。
- 不注册成 provider，不声明 `daily` / `realtime` / `minute`，避免被路由成主源。
- 不挂定时任务，不进行情 SSE 刷新。
- 空结果不落缓存。官方对增量接口写过「限流时返回空数组」，这条历史接口没有同样的句子，但空结果仍可能是限流，不能固化成「当天没有竞价」。
- 有记录的历史日会落在 `data/xtick_supplement/bidhistory/`，下次读缓存，不再打上游。

公开目录该接口的 `apiAuth` 只有 `[4]`。文档页的档位按钮顺序是青铜、白银、黄金、至尊、量化。编号不能当成配额。公开材料没有写至尊版无限，客户端按有限额度处理。

## 明确不接

这些要么仓库里已经有，要么会把补充源做成第二套行情，这一轮都不接：

| 接口 | 不接的原因 |
| --- | --- |
| 股票列表、交易日历、日 K、分钟 K、实时行情、复权 | 主源已有。再接一遍会和 TickFlow / fuyao 抢「当前价」 |
| 深度行情、分笔、日内分时 | 和现有盘口 / 分钟重叠，行数大，额度不划算 |
| 龙虎榜、资金流、连板天梯、市场情绪 | fuyao 龙虎榜、资金流和本地涨停池已经覆盖同类展示。情绪里的分档晋级率没有生产包样本，留到以后单独核字段 |
| 竞价实时 `/doc/core/bidtime`、竞价详情 `/doc/hot/biddetail` | 官方写的是盘中或 9:15–9:25 的过程数据。这一轮要避免把竞价过程当成实时行情 |
| 全市场增量 `/doc/hot/dayupdate` | 官方写明严格限流，前 20 次之后间隔随次数增加，限流时返回空数组。不适合作为补充入口 |
| 财务、股东、股本、技术指标 | 财务和指标本地已有或可算。指标接口不是 XTick 独有信息 |
| ST / 停牌 | 仓库已有 ST 区间同步。停牌样例字段和说明对不齐，不猜 |

## 日期和 seq

- 请求的 `startDate` 与 `endDate` 都是用户选的那个交易日。响应上的「数据日期」就是这个查询日。
- 上游 `time` 若落在另一天，只打警告，不用它改查询日，也不把它写成主行情的交易日。
- `time` 显示成北京时间。若是 `00:00:00`，界面写明不能解释成 09:25 撮合时刻。公开样例 `1770307200000` 就是 2026-02-06 00:00。
- 查询日晚于北京时间今天：不请求。
- 查询日是周六或周日：不请求。法定假日没有日历可拦，工作日仍可能得到空结果。
- 查询日就是今天，且北京时间早于 09:26：不请求。官方说这条接口保留的是终态，9:25 之前拉会把未完成竞价和实时行情混在一起。
- 今天且已过 09:26：可以查，标记为「当日终态，不是实时」。`live` 恒为 `false`。

`seq` 官方文本自己冲突：

- range：`0` 开盘数据，`1` 集合竞价最后一条。
- description 首句：`0` 是 9:25 最后一条，`1` 是倒数第二条。
- description 末句又说一般 `0` 是开盘、`1` 是集合竞价最后一条。

响应里的 `seq_doc.adopted_label` 固定是 `null`。界面两套说法都展示，不选一边。

## 运行时配置

不要把这些写进 Git，也不要改 `.env`、DSA 使用的环境变量、三套买卖信号环境变量或阈值锁。开关和凭据每次请求现读，写完 `secrets.json` 不用为了生效再重建容器。

环境变量未设置时，下面的 secrets.json 键可以单独打开功能。环境变量若写成 `0`、`false`、`off` 或 `no`，强制关闭，盖过 secrets.json。

| 位置 | 键 | 默认 | 作用 |
| --- | --- | --- | --- |
| `data/user_data/secrets.json` | `xtick_supplement_enabled` | 无 | `1` / `true` / `yes` / `on` 才允许出网 |
| 同上 | `xtick_api_token` | 无 | 凭据。有这个键就不必设 `XTICK_API_TOKEN` |
| 同上 | `xtick_bidhistory_allow_all` | 无 | `1` 才允许 `code=all` |
| 环境变量 | `XTICK_SUPPLEMENT_ENABLED` | 未设置 | 显式 `1` 开启；显式 `0` 强制关闭 |
| 环境变量 | `XTICK_API_TOKEN` | 未设置 | 仅当 secrets.json 没有凭据时使用 |
| 环境变量 | `XTICK_BIDHISTORY_ALLOW_ALL` | 未设置 | 显式 `0` 时即使 secrets.json 允许 all 也不放行 |
| 环境变量 | `XTICK_HTTP_TIMEOUT_S` | 15 | 限制在 1–60 秒 |
| 环境变量 | `XTICK_MIN_INTERVAL_S` | 1 | 两次真正出网的最小间隔，最大认到 30 秒 |
| 环境变量 | `XTICK_API_BASE` | `http://api.xtick.top` | 不要在值里放凭据 |

状态接口只返回「有没有凭据」，不返回凭据本身。非法代码、日期、seq 不会按原样写进响应。日志会去掉 `token=` 和凭据原文。响应体若含凭据，整包丢弃不落盘。上游连接异常不挂到返回给页面的错误上，避免异常文本带出完整 URL。

读取 ZIP 时只认成员名 `data.json`，拒绝路径穿越、过大的解压体积、过高的压缩比和超过 8000 行的包。生产观察的全市场是 5580 行，超过上限整包拒绝，避免半截结果被当成完整全市场。`data.json` 可以是 JSON 数组，或一行一个对象。

非 200、空 body、坏 ZIP、坏 JSON、超时、429、缺凭据都变成这张卡自己的状态。竞价扫描文件和主行情缓存不动。

## 最小上线

代码在镜像里，`data/` 只是卷。旧容器没有这条路由，所以**第一次装上本 PR 必须重建 app 容器**。重建时不要改 `.env`，也不要带上 dsa profile。

在已经构建出含本 PR 的镜像、并且当前目录的 `.env` 没有被改过的前提下，只重建 app：

```bash
docker compose up -d --no-deps --force-recreate app
```

这一步会让 app 重新读取现有 `.env`，但命令本身不编辑它。三套信号变量、DSA 和阈值锁都还在原来的文件里。不要执行 `docker compose up --build` 时顺手改 `.env`，也不要 `--profile dsa`。

容器起来之后，**只改 secrets.json 就能启用，不必再重建，也不必写 `.env`**。编辑 `data/user_data/secrets.json`，保留已有键，只增加：

```json
"xtick_api_token": "<凭据>",
"xtick_supplement_enabled": "1"
```

文件权限保持 `0600`，属主仍是容器用户。保存后刷新竞价页即可，进程每次请求都会重读这个文件。不要把凭据写进 shell history，也不要为了这一步去改 `.env`。

然后对一只股票、一个已经结束的交易日点一次查询。核对来源是 XTick、日期是所选日期、文案是历史或当日终态。不要为了验收去开 `all`，也不要在北京时间 09:26 前把今天的结果当成可交易竞价。

如果 secrets.json 里开关是 `1`，但环境变量 `XTICK_SUPPLEMENT_ENABLED=0`，仍然不出网。这个 `0` 是硬关闭。

## 回退

启用之后的回退**不用重建容器**：把 `xtick_supplement_enabled` 改成 `0` 或删掉该键。下一次查询就不再出网。凭据键可以留着，关闭时不会被状态接口返回。

`data/xtick_supplement/` 可以留着。关闭后它不会回写主行情。要清掉就只删这个目录。

若要连代码一起撤掉，把 app 镜像换回合并本 PR 之前的版本，再执行同一条只重建 app 的命令。不要因此改 `.env`，也不要重建 dsa。没有迁移，没有改评分、风控、触发和三套信号环境变量。

## 还没有做的事

本 PR 没有在生产再打官方接口，也没有用真实 token 做线上验收。云端或办公网对同一 URL 返回 500、空 body，不能当成官方不可用，也不能当成官方可用。上线后的第一次真实查询才是验收。
