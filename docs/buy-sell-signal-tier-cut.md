# 买卖信号 · T1 切档规则（展示层 弱 / 中 / 强）

> 批次 **20261030gt1** · `P-bss-t1-tier-cut` · 上游 #-A-#12 **闭环终锁**落地
> 规则版本：**`tier_cut_v1`**
> 对应锁面模块：[`backend/app/buy_sell_signals/tier_cut_lock.py`](../backend/app/buy_sell_signals/tier_cut_lock.py)
>
> **仅供研究，不构成投资建议；执行须人工确认。** 红涨绿跌。成本来回 18.2bp。

## 0. 这一份是什么 / 不是什么

**是**：切档规则本身 —— 档名、连续量、阈值、无量时的行为、展示必填项、与 Bonferroni
和方向标签的关系、与 T2 的先后。规则一旦写死，实现只能照它算，不能各自发挥。

**不是**：

| 不是 | 为什么要点明 |
|---|---|
| 不是校准信号 | 档是**展示强度**，不参与 calib、不进 `p25` 闸、不改任何 `CALIB_*` 常量 |
| 不是下单指令 | 档名中性（弱/中/强），不含动作动词；买/卖由方向标签表达，两者分开 |
| 不是 hits 字段 | 本拍**不**改 hits schema，档位不落盘、不进 `hits_models` |
| 不是 UI / 推送接线 | 展示层怎么画、怎么发是 T2 与观测口的事，另口令 |
| 不是放量开关 | 文档齐备只说明「规则定了」，**不**说明可放量、`TRIGGERING` 该开 |

> **文档锁 ≠ 可放量。** 这句话在整份文件里出现三次不是啰嗦：一份写得很整齐的规则
> 文档，最容易被读成「所以这套东西已经能用了」。它只说明规则不再摇摆。

## 1. 产品语义

三个档 = **展示层强度**，取值封闭为：

```
weak   → 对外文案「弱」
mid    → 对外文案「中」
strong → 对外文案「强」
```

英文键做内部标识（`TIER_LABELS = frozenset({"weak", "mid", "strong"})`），中文只做
对外文案（`TIER_LABEL_ZH`）。**不要**把中文当键用 —— 一处改了文案就成了改键。

### 1.1 档与方向是两条轴

| 轴 | 取值 | 由谁定 |
|---|---|---|
| **方向** | `research_buy` / `research_sell` / `research_watch` | `constants.DIRECTION_LABELS`（**本拍零碰**） |
| **档（强度）** | `weak` / `mid` / `strong` | 本文件 + `tier_cut_lock` |

两条轴正交：**弱买**和**强买**方向相同、强度不同；**强买**和**强卖**强度相同、方向
相反。任何把档塞进方向集合、或把方向键当档名的做法都是错的。

`DIRECTION_LABELS` 保持原三值不动，`research_watch` **保留** —— 观察档不是「最弱
的买卖」，它是另一种状态，删掉它等于把「看见了但不动」这件事从系统里抹掉。

### 1.2 禁止六词动作指令式

**禁止**用「买入 / 卖出 / 加仓 / 减仓 / 开多 / 开空」这类动作指令替代档名或方向。

原因不是用词洁癖。动作指令读起来是**已决策**，而档位只回答「这条信号有多强」。
把强度伪装成指令，等于把「研究结论」和「交易决定」压成同一句话 —— 而这两件事之间
隔着人工确认这一步，那一步不能在设计上被省掉。

## 2. 硬门：无量＝无档

> **缺连续量 → 无档。绝不用 0 顶上冒充最弱档。**

这条是终锁三条件里的第一条，也最容易在实现时被"优化"掉。写下为什么：

- `0` 在多数连续量上是一个**真实的取值**（例如行业分位垫底），不是一个"没有"的哨兵。
  拿 0 顶缺失，等于把"不知道"渲染成"最差"，用户看到的是一个确定结论，而真实情况是
  没有结论。
- 一旦允许填 0，档位分布会在缺失样本上系统性左偏，而这件事**看不出来** —— 页面
  上只有一排"弱"，没人知道其中一半是假的。

因此：

```
measure is None            → tier is None（无档）
measure 标记缺失 / 缺 rank  → tier is None（无档）
无触发连续量 / 无频率锁     → tier is None（无档）
```

"无档"是**一等状态**，不是错误、不是 0 档、不是待补。展示层遇到无档就照实说
「无档」，不要用最弱档填充、不要用「—」混过去（`—` 和「弱」在读者眼里只差一个像素）。

锁面里对应 `NO_MEASURE_NO_TIER = True`，以及可调用断言
`assert_no_measure_no_tier(has_measure=..., tier=...)`。

## 3. 日频族连续量

```
DAILY_TIER_MEASURE_ID = "q_rank_within_ind"
```

**定义**：申万一级**行业内**的质量相对分位，连续取值 ∈ `[0, 1]`，语义为百分位、
**越高越好**（0 = 本行业最低，1 = 最高）。同分并列取平均秩。

来源模块 `quality_rank.py`（**本拍零碰**，只作量锚）。它的既有约定直接继承：

- 只有「有 `q_score` 且 `q_missing_flag` 为 `False` 且行业已知」的票才有 rank 资格；
- 其余票 `q_rank_within_ind = None` + `q_missing = True` + 原因码；
- 原因码封闭集：`no_industry` / `no_q_score` / `q_missing` / `singleton_industry`。

**绝不填 0** —— 理由见 §2：0 是行业垫底的真实百分位，不是"没有"。

只要 `q_rank_within_ind is None`（不论哪个原因码）→ **无档**。单票行业
（`singleton_industry`）也算无档：只有一只票时的"分位 = 1"是算术产物，不是相对位置。

## 4. 事件族连续量

```
EVT_TIER_MEASURE_ID = "evt_excess_vs_freq_cross_section_q"
```

这个 id 串是三个词的拼接，读法写死如下，避免日后被当成随便起的名字：

| 片段 | 含义 |
|---|---|
| `evt` | 事件族（`minute_event` 轨） |
| `excess_vs_freq` | **超额倍数**：触发连续量相对其 FreqLock / 设计频率的比值 |
| `cross_section_q` | 再取 **同 `signal_id` × 同交易日截面**内的分位 |

### 4.1 建议默认定义（已钉，实现按此对齐）

1. 取该信号在当日的**触发连续量**（该事件族信号自己的强度量，例如触发次数、
   成交额倍数等，由各信号定义给出）；
2. 除以该信号的 **FreqLock / 设计频率**，得**超额倍数**；
3. 在**同 `signal_id` × 同交易日**的截面内，把超额倍数转成分位 ∈ `[0, 1]`。

第 3 步不是可选的。不取截面分位，不同 `signal_id` 之间的量纲无法比较，阈值 ⅓/⅔
会变成"对某些信号永远弱、对另一些永远强" —— 那等于没有阈值。

**无触发连续量 / 无频率锁 → 无档**（不是填 1.0，也不是填 0）。

### 4.2 两族必须各用各的量

`DAILY_TIER_MEASURE_ID ≠ EVT_TIER_MEASURE_ID`（`assert_measure_ids_distinct()` 把守）。

不可共用同一个量：日频族的 `q_rank_within_ind` 是**行业内横截面**分位，事件族的量是
**时间频率超额**再取**同 signal_id 截面**分位 —— 两者的分母根本不是同一群人。
共用一个 id 会让"这个档是怎么算出来的"永远说不清，而这正是规则版本要解决的问题。

### 4.3 算子接线不在本拍

**规则已锁；算档接线属 T2 / 观测口另口令。** 本拍不实现 UI、不实现推送、不实现
把事件族量算出来的算子。写在这里的定义是**契约**，不是已完成的功能。

> 文档锁 ≠ 可放量。

## 5. 阈值（`tier_cut_v1`）

已归一化到 `[0, 1]` 之后按下列区间切档，**左开右闭**：

| 档 | 区间 | 含义 |
|---|---|---|
| `weak` | `(0, ⅓]` | 弱 |
| `mid` | `(⅓, ⅔]` | 中 |
| `strong` | `(⅔, 1]` | 强 |

常量：`TIER_CUT_WEAK_HI = 1.0 / 3.0`、`TIER_CUT_MID_HI = 2.0 / 3.0`。

### 5.1 边界归属（N3 已拍板）

恰落在 ⅓ 上的 → **弱**（闭右端）。恰落在 ⅔ 上的 → **中**（闭右端）。这是"右闭"
的直接后果，不要在两处实现里各写一种。

### 5.2 两个必须写明的边界事实

**其一：`measure == 0` 有量但无档。** 弱档下界是**开**的，所以 0 不匹配任何档位。
这不是 bug，也不是"无量"：0 是一个真实的百分位（行业垫底 / 超额倍数最末），
它只是不落在任何切档区间里。展示层按"无档"呈现即可 —— 而这恰好与 §2 同向：
**绝不把 0 渲染成最弱档**。

**其二：`measure == 1.0` 属于强档。** 上界闭。

### 5.3 改阈值必须 bump 版本

**禁止静默改阈值不 bump。** 改量、改阈值、改映射三者任一 → `TIER_CUT_RULE_VERSION`
必须换新值（`tier_cut_v2` 起）。

理由：档位一旦展示出去，历史截图、群消息、报告里的"强"都绑定着当时那一版阈值。
不 bump 版本，两批样本会被当成同一口径比较 —— 而这种错**不会报错**，只会让结论
悄悄漂移。

## 6. 展示三项必填

任何对外展示的档位，必须同时带齐三项（`TIER_DISPLAY_REQUIRED_KEYS = ("track", "asof_grain", "mode")`）：

| 逻辑键 | 取值域 | 缺了会怎样 |
|---|---|---|
| `track`（轨） | `daily_fundamental` \| `minute_event` | 不知道这个档是哪一族算的 |
| `asof_grain`（asof 粒度） | `day` \| `minute` | 不知道这个档截到哪一刻 |
| `mode`（模式） | `shadow` \| `observation` \| `live` | 影子档被读成线上档 |

**缺一不合规**。三项一起才是"这个档是什么"的完整指认：

- 同一个 `weak`，`daily_fundamental`/`day` 和 `minute_event`/`minute` 是两件事；
- 同一个 `strong`，`shadow` 和 `live` 的可信度完全不同 —— 影子里的强只说明
  "规则在影子里算出强"，**不**说明它可以推给人看。

`track` 的取值域与 `constants.FREQ_LOCK_CADENCES = {minute_event, daily_fundamental}`
**同集合**（本拍零碰该集合，只是对齐取值）。`asof_grain` 是粒度不是节拍，故另开
`day` / `minute`，不复用节拍名 —— 节拍描述"多久评估一次"，粒度描述"截到哪一天/哪一分钟"，
两者不能互相顶替。

## 7. 展示边 Bonferroni

**本锁是展示边：不占 `BONFERRONI_M = 6`。**

- `BONFERRONI_M` 的 6 格是**校准边**预算（A1 已钉，本拍零碰数值与 scheme）；
- 档位切分是对**已产出信号**的呈现分层，不新开一次假设检验，故不申请预算格；
- 锁面常量：`TIER_CUT_BONFERRONI_DISPLAY_EDGE = True` /
  `TIER_CUT_DOES_NOT_CONSUME_BONFERRONI_M = True`。

### 7.1 非永久豁免

"不占 m" 是**当前口径**，不是永久通行证。若将来校准边要占用预算：

- 必须**新开一把锁**（新模块 / 新常量集），
- 必须**重算** `m` 并 **bump** `BONFERRONI_SCHEME_ID`，
- 不得在既有锁面上"顺手加一格"。

> **展示边 ≠ 校准边。** 把展示分层说成"不用做多重检验"，是把两件事混为一谈：
> 不做检验的是展示分层这件事本身，不是它背后的信号。

## 8. 门禁：影子 / 观测先

档位进入任何对外通道之前，顺序写死：

1. **影子（`shadow`）** —— 先算、先看，不外发；
2. **观测（`observation`）** —— 内部可见，仍不外发；
3. **真推（`live`）** —— **另口令**，且必须带旁注「**研究档 · 未放量**」。

**影子 ≠ live 模板。** 影子阶段的输出形状可以粗糙、可以缺字段、可以每天变；一旦
当成 live 模板的草稿，粗糙就会被复制到线上。真推模板的改动不在本拍，也不该由
"反正影子里已经这么写了"来推动。

## 9. 定序：T1 ≺ T2

```
T1（本文件 + tier_cut_lock）  ←  规则
        ↓  必须先定
T2（展示字段设计 / UI 接线 / 观测口）  ←  实现
```

**T1 未锁，T2 无从接线**：字段名、取值域、必填项都在 T1 里，T2 只能消费不能重定义。
反过来，T1 也不替 T2 做决定 —— 本文件不说 UI 画成什么样、不说推送文案怎么写、不说
schema 加哪些列。

本拍**只做 T1**。T2 展示字段设计、UI 接线、观测口开通、算档接线，**全部另口令**。

> **T2 字段契约已开（批次 20261030gt2）**：展示载荷字段契约见
> [buy-sell-signal-tier-display.md](./buy-sell-signal-tier-display.md)
> （锁面 `tier_display_lock.py`，版本 `tier_display_v1`）。
> 本 §9 规则正文语义**不变**；T2 **只消费不重定义**。
> 算档接线 / UI 真接线 / 观测口（#-A-#9）/ schema 进 hits / 真推旁注落地**仍全部另口令**。


## 10. 锁面模块

规则的可验形态在
[`tier_cut_lock.py`](../backend/app/buy_sell_signals/tier_cut_lock.py)：

- 纯常量 + 纯断言函数，**无 I/O**：不读行情、不写文件、不碰 `HitStore`、不调推送；
- **不算行情**、**不写 hits**、**不接线 UI / 钉钉**；
- 断言函数由**测例**调用，模块 import 时不硬 raise（否则一个常量写错会让整个包
  导不进来，错误信息还指向 import 而不是那一行）。

测例：`backend/tests/test_buy_sell_signal_tier_cut_lock.py`。
