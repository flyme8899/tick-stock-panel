## 0. 这一份是什么 / 不是什么

**是**：展示层**字段契约** —— 一个对外展示的档位载荷里，必须有哪些键、每个键的取值域、
无档怎么表达、哪些词与哪些字段一律不许出现、门禁顺序、与 T1 的接线边界。

**不是**：

| 不是 | 为什么要点明 |
|---|---|
| 不是切档规则 | 阈值/量/版本属 T1（`tier_cut_v1`），本文件**只读消费**，不重定义 |
| 不是 hits schema | 档位**不**落盘；schema 进 hits **另口令**（须规则版本 + 切档量原值 + 全套闸） |
| 不是 UI 接线 | 画成什么样、放哪个 tab、文案怎么写，**另口令** |
| 不是真推落地 | 钉钉模板**零碰**；真推旁注只在本文件写成**契约**，不落代码 |
| 不是算档实现 | 不算行情、不取数、不写文件 |
| 不是观测口 | 开通 #-A-#9 观测口**另口令** |
| 不是放量开关 | 字段契约齐备 ≠ 可放量 ≠ `TRIGGERING` 该开 |

> **字段契约 ≠ 可放量。** 这句话在本文件出现三次不是啰嗦：一份字段表写得很整齐的
> 文档，最容易被读成「所以这套东西已经能上线了」。它只说明**字段不再摇摆**。

## 1. 产品语义

三档 = **展示层强度**（非校准信号、非下单指令）。档名中性：**弱 / 中 / 强**。

### 1.1 两条轴，各自封闭

| 轴 | 取值 | 定义处 | 本拍 |
|---|---|---|---|
| **方向** | `research_buy` / `research_sell` / `research_watch` | `constants.DIRECTION_LABELS` | **零碰** |
| **档（强度）** | `weak` / `mid` / `strong`（文案 弱/中/强） | `tier_cut_lock.TIER_LABELS` / `TIER_LABEL_ZH` | **只读消费** |

两侧封闭集**都不改**。`research_watch` **保留** —— 观察档不是「最弱的买卖」，它是另一
种状态；删掉它等于把「看见了但不动」从系统里抹掉。

两条轴正交：**弱买**与**强买**同向不同强；**强买**与**强卖**同强不同向。

### 1.2 展示层不新增第三轴

本契约只认这两条轴。禁止引入「置信度」「推荐等级」「星级」之类**第三套强度表示** ——
多一套就多一处对不上的地方，而两套强度同时出现时，读者只会相信更醒目的那套。

## 2. 展示载荷必填四元组

任何对外展示的档位载荷，必须**同时**带齐四项：

| # | 键 | 取值域 | 缺失后果 |
|---|---|---|---|
| 1 | `track` | `daily_fundamental` \| `minute_event` | 不知道这个档是哪一族算的 |
| 2 | `asof_grain` | `day` \| `minute` | 不知道截到哪一刻 |
| 3 | `mode` | `shadow` \| `observation` \| `live` | 影子档被读成线上档 |
| 4 | `tier` | `weak` \| `mid` \| `strong`，**或显式无档** | 不知道强度 / 不知道是"没有" |

**缺一不合规。**

### 2.1 前三项继承 T1，第四项是 T2 的增量

这不是重定义，是**分层**：

```
T1  TIER_DISPLAY_REQUIRED_KEYS        = ("track", "asof_grain", "mode")        ← 指认"是什么"
T2  TIER_DISPLAY_PAYLOAD_REQUIRED_KEYS = 上述三项 + ("tier",)                    ← 再加"值是多少"
```

T2 的常量**由 T1 派生**（`(*_t1.TIER_DISPLAY_REQUIRED_KEYS, "tier")`），不是抄一份字面量。
抄一份的话，T1 哪天改了键名，T2 会静默地继续用旧名 —— 而派生 + 交叉断言会在那一刻红。

三个取值域也**直接引用** T1 的 `TIER_DISPLAY_TRACKS` / `TIER_DISPLAY_GRAINS` /
`TIER_DISPLAY_MODES`，不复制成员。

### 2.2 有档与无档的两种形状（N1 已拍板）

```python
# 有档
{"track": "daily_fundamental", "asof_grain": "day", "mode": "shadow",
 "tier": "mid", "no_tier": False}

# 显式无档
{"track": "minute_event", "asof_grain": "minute", "mode": "observation",
 "tier": None, "no_tier": True, "no_tier_reason": "no_trigger_measure"}
```

规则写死：

- `no_tier=True` → `tier` **必须为 `None`**；
- `no_tier=False` → `tier` **必须 ∈ `TIER_LABELS`**。

**没有第三种形状。** 「`tier` 缺键」不是无档，是**不合规** —— 缺键与"明确没有"在数据上
必须分开，否则下游无法区分「字段漏了」和「确实没算出来」。

## 3. 硬门：无量＝无档（显式）

> **无连续量 → 显式无档。禁止用 `weak` 顶缺失。**

继承 T1 §2 的全部理由，此处只补充 T2 的角度：

- **展示层是最后一道能拦住"假弱"的地方。** 上游把缺失填成 0、下游把 0 渲染成「弱」，
  中间任何一环不拦，页面上就是一片"弱" —— 而其中多少是真的弱，没人知道。
- **`no_tier` 是给读者的信号，不是给程序的补丁。** 它存在的意思是「这条没有档」，
  不是「这条算失败了」。文案须照实说「无档」，不要用「—」混过去（`—` 和「弱」在读者
  眼里只差一个像素）。

`weak` 一旦被用作缺失的填充值，**这个档名就再也不能表示"真的弱"** —— 这是不可逆的
语义污染。所以这条是硬门，不是风格建议。

## 4. 禁止项

### 4.1 六词动作指令式

**禁止**出现（及同义动作指令式）：

| 买向 | 卖向 |
|---|---|
| 可以买入 / 建议买入 / 强烈买入 | 可以卖出 / 建议卖出 / 强烈卖出 |

另禁把 **买 / 卖 / 加仓 / 减仓 / 开多 / 开空** 当作档名或载荷文案。

理由不是用词洁癖：动作指令读起来是**已决策**，而档位只回答「这条信号有多强」。把强度
伪装成指令，等于把「研究结论」和「交易决定」压成同一句话 —— 而这两件事之间隔着人工
确认，那一步不能在设计上被省掉。

### 4.2 措辞检查的两种匹配方式（工程判断，写在明处）

锁面对两类词用**不同**的匹配方式，这是刻意的：

| 类别 | 例子 | 匹配方式 | 为什么 |
|---|---|---|---|
| 长短语（六词） | 「建议买入」 | **子串匹配** | 四字短语误报率低，可全文案扫 |
| 短词（买/卖/加仓…） | 「买」「卖」 | **只查档名**（封闭短串） | 中文里「买卖信号」是本项目名，子串扫必然误报 |

短词做全文子串扫描**一定会炸**在本项目自己的名字上。所以短词只用于档名这种封闭、
短、且本来就该中性的字符串。**这条限制是设计的一部分，不是漏做** —— 宁可说清检查
边界，也不要写一个"看起来全覆盖、实际天天误报"的守卫，那样它很快会被加 `# noqa` 关掉。

### 4.3 价格 / 数量 / 仓位 / 订单

展示载荷内**禁止**这些字段：

```
price / quantity / position / order / 价格 / 数量 / 仓位 / 订单
```

理由：这是**研究档**的展示载荷。一旦载荷里出现价量仓单，下游任何一段代码都可以"顺手"
把它当成下单参数用 —— 而它本来只是一句话的强度描述。字段存在本身就在邀请越界。

> 载荷里也不该出现任何「按此执行」的暗示。档位是描述，不是委托。

## 5. 门禁

### 5.1 顺序写死

```
shadow（影子）  →  observation（观测）  →  live（真推，另口令）
                                     ↑
                        必须带旁注「研究档 · 未放量」
```

- **影子**：先算、先看，不外发；
- **观测**：内部可见，仍不外发；
- **真推**：**另口令**，且载荷旁注固定为「**研究档 · 未放量**」。

### 5.2 影子 ≠ live 模板

影子阶段的输出形状可以粗糙、可以缺字段、可以每天变。一旦有人把影子当 live 模板的草稿，
粗糙就会被复制到线上。所以：

- `mode="shadow"` 的载荷**不得**直接改 `mode="live"` 后发出；
- 真推模板的改动**另口令**，且不在本仓本拍落地。

### 5.3 本拍只写契约

**本文件不改钉钉真推模板代码，不改推送文案主路径。** 旁注在这里是**契约文本**，
落地进代码属另口令。

## 6. Bonferroni

**本锁是展示边：不占 `BONFERRONI_M = 6`。**

- 6 格是**校准边**预算（A1 已钉），本拍零碰数值与 scheme；
- 档位字段契约是对**已产出信号**的呈现约定，不新开假设检验，故不申请预算格。

### 6.1 非永久豁免

「不占 m」是**当前口径**，不是永久通行证。若将来校准边要占用预算：必须**新开一把锁**、
**重算** `m` 并 **bump** `BONFERRONI_SCHEME_ID`，不得在既有锁面上"顺手加一格"。

> **展示边 ≠ 校准边。** 不做检验的是"展示字段契约"这件事本身，不是它背后的信号。
